# מי בטיול?

אפליקציית ווב לבעלי כלבים: לוחצים "יצאתי לטיול" והופכים לגלויים על ראדאר חי למטיילים אחרים בקרבת מקום.

## למה זה בק-אנד עצמאי ולא Artifact

הגרסה הראשונה נבנתה כ-Artifact של Claude, אבל התברר שהמסגרת (iframe) שדרכה Claude מציג
Artifacts לא מעבירה (delegates) הרשאת `geolocation` לדף המוטמע — כך ששירותי המיקום
נחסמים שם תמיד, בלי קשר להרשאות בדפדפן או במערכת ההפעלה. הפתרון: שרת Node קטן משלנו,
שמוגש כדף רגיל בדפדפן (לא בתוך iframe) — שם שירותי מיקום עובדים כרגיל.

## מבנה הפרויקט

```
server.js          שרת Express + Socket.IO, מחזיק בזיכרון את רשימת המטיילים הפעילים
public/index.html  כל הממשק (עיצוב, ראדאר, טופס פרופיל) - עמוד יחיד
public/manifest.json + icon-192.png/icon-512.png  PWA אמיתי - אפשר "להוסיף למסך הבית"
public/sw.js        Service Worker (מטמין את מעטפת האפליקציה + מציג התראות Push)
data.json           נוצר אוטומטית בהרצה ראשונה: מועדפים (כוכב) ומנויי Push. לא לשתף/להעלות ל-git.
vapid.json          נוצר אוטומטית בהרצה ראשונה: מפתחות VAPID לשליחת Push. סודי - לא לשתף/להעלות ל-git.
```

## התראות "בוא/י לגינה" (Push)

אפשר לסמן כלב בכוכב ⭐, ואם גם הוא/היא סימנו אתכם בחזרה (הדדי) - מופיע כפתור
"🐾 בוא/י לגינה" ששולח התראת Push למכשיר שלהם, גם אם האפליקציה אצלם סגורה לגמרי.

**חשוב - זה עובד רק עם HTTPS אמיתי.** Push דורש הקשר מאובטח; `localhost` על אותו מחשב
עובד לבדיקה עצמית, אבל חברים שנכנסים מהטלפון שלהם דרך כתובת הרשת המקומית (למשל
`http://192.168.x.x:3000`) **לא יוכלו** לקבל התראות בכלל, גם אם יאשרו הרשאה - הדפדפן
פשוט חוסם רישום ל-Push על חיבור לא מאובטח. כדי שזה יעבוד עבור אנשים אחרים, צריך את
הפריסה עם HTTPS (ראו למטה).

**אייפון**: התראות Push בספארי עובדות רק אם האפליקציה הותקנה למסך הבית (iOS 16.4+).
משתמשי אייפון שעדיין לא התקינו יראו הודעה בראש המסך עם הנחיה להוסיף למסך הבית.

## הרצה מקומית

```bash
npm install
npm start
```

האפליקציה תרוץ על http://localhost:3000 . שימו לב: שירותי מיקום בדפדפן דורשים HTTPS,
חוץ מ-`localhost` שנחשב "הקשר מאובטח" גם הוא - כך שהרצה מקומית לבדיקה תעבוד.
לבדיקה עם מיקום GPS אמיתי מנייד, צריך פריסה עם HTTPS אמיתי (השלב הבא).

## פריסה לאינטרנט (כדי שזה יעבוד באמת בנייד, עם HTTPS)

כל אחת מהאפשרויות הבאות מתאימה (שרת Node "רגיל" עם תמיכה ב-WebSocket):

**Render** (render.com) - הכי פשוט להתחלה:
1. מעלים את הפרויקט לריפו ב-GitHub.
2. יוצרים "New Web Service", מחברים לריפו.
3. Build Command: `npm install`, Start Command: `npm start`.
4. Render נותן כתובת HTTPS מוכנה אוטומטית.

**Railway** (railway.app) או **Fly.io** - דומה: מחברים ריפו/deploy מה-CLI, מגדירים
`npm start` כפקודת ההרצה, ומקבלים כתובת HTTPS.

⚠️ **חשוב**: לא להשתמש בפלטפורמת serverless "ללא שרת קבוע" (כמו Vercel Functions
הרגילות) - Socket.IO צריך חיבור מתמשך (WebSocket), וזה דורש שרת Node "חי" ולא פונקציה
שרצה לבקשה בודדת ונעצרת.

## המגבלה הכי חשובה של הגרסה הזו: אחסון בזיכרון

`server.js` שומר את רשימת המטיילים הפעילים ב-Map בזיכרון (`walkers`). המשמעות:

- **איפוס בכל ריסטארט** - אם השרת קורס או מתעדכן, כל מי שהיה "בטיול" נעלם (יצטרך ללחוץ
  שוב על הכפתור). לא נורא ל-MVP, אבל לא מתאים לייצור אמיתי.
- **לא עובד עם כמה מופעים (instances)** - אם בעתיד תרצו להריץ יותר משרת אחד למקביליות,
  כל מופע יראה קבוצת מטיילים שונה. חייבים להגדיר "1 instance" בפלטפורמת הפריסה כרגע.

**הצעד הבא הטבעי**: להחליף את ה-`Map` באחסון אמיתי - Redis (מתאים מאוד ל"מי פעיל עכשיו",
עם TTL מובנה) או Postgres. גם Render וגם Railway מציעים את שניהם בלחיצת כפתור.

## מה עוד שווה להוסיף לפני השקה ציבורית

- הרשמה/אימות משתמשים אמיתיים (כרגע הזהות היא מזהה אקראי שנשמר בדפדפן - כל מי שינקה
  cookies/local storage "יתחיל מחדש").
- הגבלת קצב (rate limiting) על אירועי ה-Socket.IO כדי למנוע spam.
- HTTPS (מגיע בחינם מכל אחת מהפלטפורמות שהוזכרו למעלה).
- מדיניות פרטיות ברורה למשתמשים - המיקום המדויק שלהם משודר לכל מי שבטיול פעיל.
